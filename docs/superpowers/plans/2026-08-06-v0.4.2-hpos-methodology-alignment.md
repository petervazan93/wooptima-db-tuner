# v0.4.2 HPOS and Methodology Alignment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prevent unavailable HPOS evidence from becoming a definitive migration finding and make current documentation distinguish executable automation, collected diagnostics, and manual advisory work.

**Architecture:** Audit publishes explicit HPOS option and table statuses with exact empty-result, command-failure, and malformed-output semantics. Rules require explicit disabled option evidence, known legacy orders, and an absent HPOS table before recommending migration; reports remain read-only. Current documentation is then reconciled against executable rules and divided into automated, diagnostic, and manual layers without changing historical dated documents.

**Tech Stack:** Bash 4+, AWK, MariaDB SQL, Bats, Docker Compose, Markdown, standard grep contract checks.

## Global Constraints

- Begin only after the desired-state completion gate and the existing P2 plan `docs/superpowers/plans/2026-08-05-p2-audit-accuracy.md` pass.
- Do not duplicate or reopen P2 listener classification or WordPress `auto-on` tasks.
- Freeze the HPOS option evidence key as `hpos.status=known|unknown_absent|unknown`.
- Freeze the HPOS table evidence key as `wc_orders_status=present|absent|unknown`.
- An absent table never emits `wc_orders_count=0`; row count remains unavailable.
- `R-APP-HPOS MIGRATE` requires explicit disabled option evidence, known `legacy_order_count > 0`, and `wc_orders_status=absent`.
- WordPress and WooCommerce findings remain read-only and recommendation-only.
- Do not add HPOS row-count reconciliation or automatic migration.
- Preserve current JSON key names unless this plan explicitly adds the two frozen status keys.
- Do not manually edit or commit generated files under `dist/`.
- Write every regression test first and verify its intended red-green transition.
- Keep all code comments in English.
- Do not modify historical dated specifications or older plans.
